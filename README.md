# LLM-GOAP Project

> **LLM 当导演定规则，GOAP 当居民做执行，玩家当观察者看演化。**

基于 **LLM 规则生成 + GOAP 自主规划** 双层 AI 架构的模拟经营游戏（类《辐射避难所》风格）。AI 不是开发工具，而是游戏的核心机制：上层 LLM 低频担任"规则制定者"，生成宏观规则、每日天气脚本与 NPC 人格；下层 GOAP（Goal-Oriented Action Planning）驱动每个 NPC 高频自主决策；玩家以有限干预引导并观察一个 AI 自治小镇的长期演化。

**实验性项目**：不追求可玩性与成品完整度，玩法只是 AI 机制的实验载体，**可扩展性是架构的第一验收标准**。当前阶段唯一目标：交付一个双层 AI 闭环完整、可运行可演示的最小可玩单元（范围与验收标准见 `Docs/DESIGN.md` §6）。

## 双层 AI 架构

```
玩家(宏观指令)
      │
      ▼
┌─────────────────────────────┐
│  LLM 层"规则制定者"(低频)     │  每游戏日一次 + 事件驱动
│  · 规则配置 JSON             │
│  · 每日世界脚本（天气等）     │
│  · NPC 人格 / 目标 / 背景    │
└──────────────┬──────────────┘
               │  只写数据，永不直接修改状态
               ▼
┌─────────────────────────────┐
│  规则验证层(每次LLM输出必经)   │  Schema校验 → 沙盒模拟 → 应用或回退
└──────────────┬──────────────┘
               ▼
┌─────────────────────────────┐
│  GOAP 层"行动执行者"(高频)    │  每个 NPC 独立 A* 规划器
│  World State → Goal → Action │  环境变化时实时重规划
└─────────────────────────────┘
```

三条职责铁律（完整设计见 `Docs/DESIGN.md` §3.2）：

1. LLM 只产出结构化 JSON 配置，**永不直接修改游戏状态、永不生成代码**；
2. **GOAP 引擎是唯一的状态修改者**；
3. LLM 调用只在游戏日边界或事件触发时发生，**不在帧循环中同步等待 API**；API 失败一律回退内置默认。

## 技术栈

| | 选型 |
|---|---|
| 游戏引擎 | **Unity 2022.3.15f1c1**（C#） |
| GOAP 核心 | 自主实现，headless 模拟内核可脱离渲染独立运行与测试 |
| AI 推理 | LLM API（面向接口 `ILLMProvider`，厂商可替换） |
| 内容扩展 | JSON 配置驱动：Action / Goal / 规则 / NPC 人格 / 每日脚本，新增内容不改引擎代码 |

## 快速开始

1. 用 Unity Hub 打开本工程，**版本须为 2022.3.15f1c1**（版本不一致可能无法打开）。
2. 编译：编辑器打开工程即自动编译（Assembly-CSharp）。
3. 测试：编辑器 Window → General → Test Runner 运行 EditMode/PlayMode 测试（CLI 命令见 `Docs/AGENT_COMMON.md` §7）。

> 已知问题：`Packages/manifest.json` 含 `file:D:/...` 形式的本机绝对路径（处理计划见 `HANDOFF.md`），其他机器打开可能报包解析错误，修复前可忽略或本地删改。

## 协作方式

**接力式开发**：人与 AI agent 均不设固定分工，谁有空谁推进。约定：工作开始前读、结束前更新 `HANDOFF.md`；重大设计决策落 `Docs/DESIGN.md` 不留在对话里；一段工作结束打检查点（更新 HANDOFF.md + git 提交），产生新提交后即 push。

AI agent 接力工作的完整约束（模型路由表、检查点工作流、每日日志机制等）见 `Docs/AGENT_COMMON.md`；各 agent 平台的入口文件（`CLAUDE.md` 等）只含指针与平台特有机制，约束正文不复制、不分叉。
