# 监管小组

本项目是接力式协作，大量文档与计划由 AI 产出（DESIGN.md、AGENT_COMMON.md、HANDOFF.md、devlog、JSON Schema、任务卡），没有人肉评审环节。监管小组是常设的独立审查机制，对 AI 产出做三类检查——**自相矛盾、不合理、违反红线**——并产出可追溯的报告。

铁律：**只报告，不修改**。监管是建议者不是决策者；修不修、怎么修由用户决定后走正常接力流程。

## 小组成员

| 成员 | 定义文件 | 职责 |
|------|----------|------|
| 一致性审查员 | `.claude/agents/consistency-reviewer.md` | 找自相矛盾：文档内部、文档之间、与代码/schema 现状 |
| 合理性审查员 | `.claude/agents/feasibility-reviewer.md` | 找不合理：偏离目标、不可行、重大遗漏 |
| 红线合规审计 | `.claude/agents/compliance-auditor.md` | 对照 §3/§4 红线与工程约定逐条审计 |

## 审查范围

- 用户指定了对象就审指定对象（文件、目录或"本次改动"均可）。
- 未指定：审**本次会话改动过的文档与计划**（用 `git status`/`git diff` 判定）；仍无可指认时向用户询问。
- 属于范围：`Docs/*.md`、`HANDOFF.md`、计划/任务卡、`Docs/schemas/`（schema 与 examples）。
- 代码不审质量，仅在核对"文档与实现是否一致"时作事实参照；代码审查另有专门工具（如 /code-review）。
- 历史 devlog 默认不审（编年史，不承载设计决策），用户点名除外。

## 流程

1. **确定对象**：按上文范围确定文件清单，明确"审什么"再开工。

2. **模型路由自查（AGENT_COMMON §6，按对象分档）**：审查对象含设计级文档（`Docs/DESIGN.md`、架构方案、技术决策文档）→ 应使用 **glm-5.3**（完整版，glm-5.2 亦可）；仅文书级（HANDOFF.md、devlog 等）→ **glm-5.3-flash**。当前模型不符时停下说明（中文）："当前模型为 X，本次审查对象为 Y，建议切换为 Z（/model 切换）"，等用户确认；用户明确坚持时照做，但必须在报告的执行模型一行注明风险。

3. **并行派出三个成员**：在同一条消息里并行调用三个 agent（各自独立、互不见对方的发现，避免锚定）。给每个成员的提示词包含：本次审查对象的确切文件清单；用户本次关注的重点（如有）；输出要求——每条发现带严重度、位置（`路径:行号`）、原文证据。对象为设计级文档时，派单尽量为成员显式指定同档模型（子代理默认档位可能低于主会话；无法指定时须在报告执行模型行注明偏差）。

4. **汇总写报告**：合并三份发现，去重（同一问题被多人发现只留一条，注明几处印证），按严重度排序，写入 `Docs/reviews/YYYY-MM-DD-<slug>.md`（当天日期，slug 为对象的英文短横线名，如 `2026-09-10-design-handoff.md`）。结论三态：**通过 / 有硬伤需修复 / 有疑点待人判断**。有硬伤（自相矛盾或违反红线）必须排在最前并在汇报首行点出。

5. **汇报**：2–4 行：结论、最重的发现（如有）、报告路径、建议下一步；末行注明执行模型与路由符合性（如"执行模型：glm-5.3-flash（按 §6 分档，本次对象为文书级）"，偏离需说明原因）——模型路由的执行情况必须可追溯。

## 报告模板

````markdown
# 监管审查报告：YYYY-MM-DD（对象）

- 审查对象：（文件清单）
- 执行模型：（模型标识 + 路由分档依据；偏离需注明风险）
- 结论：通过 / 有硬伤需修复 / 有疑点待人判断

## 发现

（按严重度排序；每条：[严重度] 问题一句话 + 位置 + 原文证据 + 说明 + 建议）

## 复审建议

（哪些发现修复后需要复审；无则写"无"）
````

## 边界

- **只报告，不修改**：不改被审文档，不直接动手修复；报告里的"建议"仅是建议。
- 报告文件**随下一次检查点提交**（本流程自身不 git commit、不 push）。
- 每条发现必须带位置与原文证据；硬伤（矛盾/违反红线）与判断（合理性疑点）分开标注，不允许把口味包装成硬伤。
- 三成员相互独立并行，不共享中间发现；汇总只做去重与排序，不替成员改判。
- 本技能与 `.claude/agents/` 定义随仓库入库，协作者拉取后同样可用；其他平台的 agent 阅读本文档、手动执行同一流程（同 checkpoint 惯例）。
- 无发现就如实报"通过"，不为凑数制造发现。
